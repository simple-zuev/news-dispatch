# Public Reader Deployment

The public GitHub Pages site is generated by GitHub Actions. On push to `main`
and four times per day, the Pages workflow renders the reader into `site/`,
validates the generated output, uploads `site/` as the Pages artifact, and
deploys that artifact.

Do not commit generated `site/` artifacts for reader UI changes. Change the
source-controlled renderer, CSS, tests or docs that own the behavior, then let
the Pages workflow rebuild the published site from the current pipeline.

The deploy build uses:

```bash
python3 tools/build_site.py --ranking-mode live --media-mode skip
```

Keep `--media-mode skip` for Pages until the media resolver is stable enough for
unattended deploys. This avoids making publication depend on remote media
lookups.

The live deploy is blocked when the reader inventory is stale or too sparse.
The freshness gate requires recent material from several streams and
independent sources. The hourly production smoke check covers the homepage,
News, Today, Digests, Sources, the build timestamp, and the newest published
reader item.

News feeds keep a bounded 14-day reader archive. The Pages workflow restores a
non-published workflow cache before rendering, merges only items that previously passed
reader policy, removes duplicates and entries older than 14 days, and saves the
cache only after all reader checks pass. The history file is neither committed
to the repository nor included in the public Pages artifact.

After a deploy, check the published reader:

```text
https://simple-zuev.github.io/news-dispatch/
```
